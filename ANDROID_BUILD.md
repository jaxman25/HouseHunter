# Android Build Guide (EAS)

How to produce an **installable APK** for testing and an **AAB** for Google Play for
*House Hunter / Ascend Hunters*.

Everything below runs from the project root.

---

## 1. Project facts

| Item | Value |
|---|---|
| Expo SDK | 57 (`expo@~57.0.29`) |
| React Native | 0.86.3 (New Architecture, always on in SDK 57) |
| EAS project | `house-hunter` under account **`johnbundi`** (`extra.eas.projectId` in `app.json`) |
| Android package | `com.househunter.app` |
| App name | House Hunter |
| Version name | `1.0.0` (`expo.version` in `app.json`) |
| Version code | **managed remotely by EAS** (`cli.appVersionSource: "remote"`, starts at `1`) |
| Native projects | **not committed** — `android/` and `ios/` are generated by Expo Prebuild (CNG) on every EAS build |
| Build config | `eas.json` (profiles: `development`, `preview`, `production`) |

### Build profiles (`eas.json`)

| Profile | Output | Distribution | Use |
|---|---|---|---|
| `development` | **APK** | internal | Dev client build (`expo-dev-client`) for day-to-day development |
| `preview` | **APK** | internal | Installable test build — this is the file you put on a phone |
| `production` | **AAB** | store | Google Play release (auto-increments the version code) |

`preview` and `development` set `android.buildType: "apk"` explicitly, so they never
emit an AAB. `production` sets `android.buildType: "app-bundle"`.

### This is a CNG (Prebuild) project

`android/` and `ios/` are **not** part of the repo (they were removed when the project
was switched to CNG). EAS Build runs `expo prebuild` in the cloud from `app.json` +
`app.config.js` on every build, so `app.json` is the single source of truth for the
package name, version, icons, splash screen, permissions and plugins.

Consequences:

- Never commit `android/` or `ios/`. Keep them out of the repo rather than gitignoring
  them: EAS Build's Android job fails with `ENOENT .../android/gradlew` in the
  *Fix gradlew* phase when `/android` / `/ios` are in a `.gitignore` of a repo that ever
  committed those folders (<https://github.com/expo/eas-cli/issues/2958>). That is why
  this project's `.gitignore` explains the rule instead of enforcing it.
- If you run `npx expo prebuild` locally for a native test, **delete the generated
  `android/` folder before your next EAS build** (or use `--local` builds only).
- `npx expo run:android` still works locally — it re-prebuilds automatically.
- Native-level changes must be made through config plugins / `app.config.js`, not by
  editing generated files.

## 3. Environment variables — do this before building

The app reads its Firebase/Maps/Cloudinary/Sentry config from `EXPO_PUBLIC_*` variables
(see `.env.example`). **`.env` is gitignored, so it is not uploaded to EAS Build** — a
cloud build that cannot see these values produces an app that throws on launch, because
`src/utils/env.ts` fails fast in release builds when the required Firebase values are
missing.

The values are therefore stored on EAS as **environment variables**, one set per
environment, and each build profile is wired to one (`eas.json` → `environment`):

| Profile | EAS environment |
|---|---|
| `development` | `development` |
| `preview` | `preview` |
| `production` | `production` |

The `preview` and `production` environments are already populated. To review, update or
re-create them:

```bash
# list what a build will receive
eas env:list preview

# push a local .env file to an environment (skips empty values)
eas env:push preview --path .env --force
eas env:push production --path .env --force

# set one variable explicitly (all EXPO_PUBLIC_* values are client-side/public)
eas env:set --name EXPO_PUBLIC_FIREBASE_API_KEY --value <value> \
  --environment preview --visibility plaintext

# pull the cloud values back into a local .env
eas env:pull preview
```

> `eas env:push` rejects empty values, so push a file that only contains the variables
> you actually set. A quick way to build one:
> `grep -E "^EXPO_PUBLIC_[A-Z0-9_]+=.+" .env > .env.eas-push`

Required (the app **throws at startup** without these): `EXPO_PUBLIC_FIREBASE_API_KEY`,
`EXPO_PUBLIC_FIREBASE_AUTH_DOMAIN`, `EXPO_PUBLIC_FIREBASE_PROJECT_ID`,
`EXPO_PUBLIC_FIREBASE_MESSAGING_SENDER_ID`, `EXPO_PUBLIC_FIREBASE_APP_ID`.

Needed for full functionality: `EXPO_PUBLIC_GOOGLE_MAPS_ANDROID_API_KEY` (blank map
otherwise), `EXPO_PUBLIC_CLOUDINARY_CLOUD_NAME` / `..._UPLOAD_PRESET` /
`..._VIDEO_PRESET` (image + video uploads), `EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID` /
`..._ANDROID_CLIENT_ID` (Google sign-in), `EXPO_PUBLIC_SENTRY_DSN` (crash reporting).

No private secret is required at build time: Firebase's web config, the Maps keys, the
Cloudinary unsigned presets and the reCAPTCHA **site** key are all client-side values.
Cloudinary's API key/secret and the Resend key live only in Cloud Functions
(`firebase functions:secrets:set ...`) and never enter the app bundle.

## 4. Build the test APK (the installable file)

```bash
eas build --profile preview --platform android
```

That single command produces the `.apk`. Add `--non-interactive` for CI. To build
without a global install: `npx eas-cli build --profile preview --platform android`.

What happens:

1. EAS uploads the repo (gitignored files such as `android/`, `ios/`, `.env` are excluded).
2. It runs `expo prebuild` to generate `android/` from `app.json`, injecting the Google
   Maps key from the `preview` environment.
3. It signs the APK with the project's EAS-managed keystore
   (`Build Credentials <id> (default)`).
4. First build of a project initializes the remote version code (currently `1`).

Typical duration: 10–20 minutes (queue time varies).

### Where the APK download link comes from

When the build finishes, the CLI prints the build page URL, e.g.

```
https://expo.dev/accounts/johnbundi/projects/house-hunter/builds/<build-id>
```

Open that page and use the **Install** button (or **Download** → `.apk`). Other ways to
find the link later:

```bash
eas build:list --platform android --limit 5          # recent builds + IDs
eas build:view <build-id>                            # URL + artifact details
eas build:list --platform android --limit 1 --json   # machine-readable (artifacts.buildUrl)
```

The direct download URL is `artifacts.buildUrl` on the build object and it stays valid
for as long as EAS keeps the artifact (unexpired build artifacts are downloadable).
The APK itself is **not** committed to this repo.

### Install it on an Android phone

1. Open the build page/download link **on the phone** (or transfer the `.apk` file).
2. Android will ask to allow installs from this source — accept
   (Settings → Apps → Special access → Install unknown apps).
3. Tap the downloaded `.apk` → **Install** → open *House Hunter*.
4. If Android reports *"App not installed"*, uninstall any earlier House Hunter build
   signed with a different key, then install again.

Via USB + adb instead:

```bash
adb install -r house-hunter.apk
```

## 5. Build the production AAB for Google Play

```bash
eas build --profile production --platform android
```

- `production` sets `android.buildType: "app-bundle"` → produces an `.aab`.
- `autoIncrement: true` bumps the remote version code on every production build.
- The AAB is signed with the same EAS-managed keystore, which is what Play App Signing
  expects.

Then upload to Play:

```bash
eas submit --profile production --platform android
```

`eas submit` needs a Google Play **service account key** (Play Console → Setup → API
access → create a service account, grant *Release* permissions, download the JSON, then
`eas submit --platform android --service-account-key-path ./play-service-account.json`).
`eas.json` sets `submit.production.android.releaseStatus: "draft"`, so submissions land
in an unpublished draft track — promote manually in the Play Console when ready.

Alternatively, build the AAB and upload it by hand in the Play Console
(Production → Create new release → upload the `.aab`).

### Credentials

Android credentials are stored on EAS (server-managed keystore), so nothing key-related
is in the repo:

```bash
eas credentials --platform android    # inspect / download the keystore, manage FCM
```

Keep a backup of the keystore: if it is lost and Play App Signing is not in use, you
cannot ship updates to an existing install.

### Versioning

- `versionName` (shown to users) comes from `expo.version` in `app.json` → `1.0.0`.
- `versionCode` (used by Play/Android) is owned by **EAS remote versioning** because
  `cli.appVersionSource` is `"remote"`. EAS warns that the `android.versionCode` value in
  `app.json` is ignored for cloud builds — it is kept only as a sane default for local
  prebuilds and to document the starting point.
- Inspect / set it:

```bash
eas build:version:get --platform android
eas build:version:set --platform android   # e.g. if you migrate from another store listing
```

> If you would rather manage `versionCode` yourself in `app.json`, set
> `cli.appVersionSource` to `"local"` in `eas.json` and bump `expo.android.versionCode`
> before each production build.

## 6. Push notifications (FCM V1) — needed for real device pushes

`src/services/notificationService.ts` calls `Notifications.getExpoPushTokenAsync({ projectId })`,
where `projectId` is the `app.json` value at `extra.eas.projectId`, and `AuthContext`
persists the token to `users/{uid}.expoPushToken` on sign-in. On Android that call needs
**FCM V1 credentials** registered against the EAS project; without them the build still
succeeds but registration fails at runtime and the saved-search Cloud Function has no
token to push to.

### Register the FCM V1 key (one-time)

1. Firebase Console → project **househunter-f3ff3** → ⚙ Project settings → **Service
   accounts** → **Generate new private key** (downloads a JSON file). Treat it as a
   secret and keep it *outside* the repo (e.g. `~/Desktop/keys/`) —
   `scripts/pre-commit-secrets-check.sh` blocks committing service-account keys.
2. Register it with EAS — either in the CLI:

   ```bash
   eas credentials --platform android
   # → app: com.househunter.app → Google Service Account → Upload/Manage FCM V1 key → pick the JSON
   ```

   or in the browser: <https://expo.dev/accounts/johnbundi/projects/house-hunter/credentials>
   → Android → *Google Service Account Key for Push Notifications (FCM V1)*.
3. Confirm it stuck: re-run the same `eas credentials --platform android` and check the
   FCM V1 entry shows a service-account address and the Firebase project.

The key is injected during prebuild, so artifacts built before it never carry it —
**rebuild after registering**:

```bash
eas build --profile preview --platform android
```

### Verify on a device

Use a real phone; images and emulators without Play services register nothing.

1. Install the APK and sign in.
2. Firestore → `users/{uid}` → the `expoPushToken` field should appear
   (`persistPushToken` writes it on sign-in and re-writes it on foreground).
   Missing while the permission is granted = registration failed: check the Metro log
   for the `No extra.eas.projectId` warning first (the code names the id explicitly
   instead of letting expo-notifications infer it).
3. Send a test push to that token from <https://expo.dev/notifications>, or wait for the
   scheduled saved-search Cloud Function.

Reference: <https://docs.expo.dev/push-notifications/fcm-credentials/>

## 7. Local builds (optional)

Requires the Android SDK, `ANDROID_HOME`, and JDK 17/21. EAS cloud builds do **not**
need any of this.

```bash
npx expo prebuild --platform android        # generate android/ from app.json
npx expo run:android                        # debug build on a device/emulator
npx expo run:android --variant release      # release APK, signed with the debug keystore
```

A locally built release APK is signed with the debug key, so it cannot be installed over
an EAS-built APK (uninstall first). Use it for smoke tests only — the EAS `preview`
build is the file to hand to testers.

## 8. What `app.json` controls (and where the assets are)

| Setting | Value | Notes |
|---|---|---|
| `android.package` | `com.househunter.app` | Google Play identity — changing it later means a new listing and new OAuth/Maps registrations |
| `android.versionCode` | `1` | local default; the EAS value is authoritative (see above) |
| `android.permissions` | location (fine/coarse), camera, external storage | `expo-location`, `expo-image-picker`, `expo-notifications` and `expo-calendar` add their own permissions (notifications, calendar, audio, vibrate, internet) during prebuild |
| `icon` | `./assets/icon.png` | **1024×1024** launcher icon (dark `#061023` logo) |
| `android.adaptiveIcon` | `./assets/adaptive-icon.png` + `#061023` | **1024×1024 with transparency**, artwork inside the 66 % safe zone so it survives every Android 8+ mask |
| `expo-splash-screen` plugin | `./assets/splash.png`, `imageWidth: 220`, `#061023` | splash logo on the brand background colour |
| `expo-notifications` plugin | `./assets/notification-icon.png`, color `#22C55E` | **96×96 white-on-transparent silhouette** (Android tints and masks it) |
| `@sentry/react-native` plugin | *not configured* | deliberately absent from `plugins` — crash reporting still runs, JS source-map upload is off (see *Sentry source maps*) |

`assets/loader.png` is not referenced by any config (kept in sync with the new
artwork, but unused — safe to delete).

> The splash and adaptive-icon background colour (`#061023`) is sampled from the brand
> artwork's own background. If you want the old white splash instead, change
> `expo-splash-screen.backgroundColor` (and `android.adaptiveIcon.backgroundColor`)
> in `app.json` back to `#FFFFFF`.

### Sentry source maps (config plugin intentionally not enabled)

Crash reporting is **on**: `@sentry/react-native` is a dependency,
`src/utils/monitoring/sentry.ts` calls `initSentry()` with
`EXPO_PUBLIC_SENTRY_DSN`, and the native SDK is autolinked by Metro/Gradle.

JS **source-map upload is off**, by configuration rather than by an env-var bypass:
the `@sentry/react-native` entry is absent from `app.json` → `plugins`. That entry is
what applies `sentry.gradle`, which hooks `sentry-cli` into the release bundling task.
With it present and no token configured, **every release build fails** in Gradle:

```
Execution failed for task ':app:createBundleReleaseJsAndAssets_SentryUpload_...'
> Process '...sentry-cli' finished with non-zero exit value 1
error: Auth token is required for this request.
```

(The previous state also carried `TODO_YOUR_SENTRY_ORG` / `TODO_YOUR_SENTRY_PROJECT`
placeholders, so the upload could never have succeeded.) Until it is configured, JS
stack traces in Sentry appear minified — native crashes are unaffected.

#### Turn source-map upload on — step by step

Do steps 1–4 *before* your next build: the plugin present without a token breaks every
release build.

1. **Sentry project** — create (or reuse) one with the *React Native* platform and copy
   three values: the **DSN**, the **organization slug**, the **project slug**.
2. **DSN (runtime)** — `.env` gets `EXPO_PUBLIC_SENTRY_DSN=<dsn>` (declared in
   `.env.example`), then push the values to the build environments:

   ```bash
   grep -E "^EXPO_PUBLIC_[A-Z0-9_]+=.+" .env > .env.eas-push
   eas env:push preview --path .env.eas-push --force
   eas env:push production --path .env.eas-push --force
   rm .env.eas-push
   ```

3. **Slugs (build time)** — add as the last entry of `app.json` → `plugins`:

   ```json
   ["@sentry/react-native", { "organization": "<org-slug>", "project": "<project-slug>" }]
   ```

   Nothing extra to install: the plugin ships inside `@sentry/react-native`. It is what
   applies `sentry.gradle`, hooking `sentry-cli` into the release bundling task.
4. **Token (secret, never committed)** — a token with the `project:releases` scope, for
   *every* environment you build with:

   ```bash
   eas env:set --name SENTRY_AUTH_TOKEN --value <token> --environment development --visibility secret
   eas env:set --name SENTRY_AUTH_TOKEN --value <token> --environment preview --visibility secret
   eas env:set --name SENTRY_AUTH_TOKEN --value <token> --environment production --visibility secret
   ```

5. **Rebuild** — `android/` is untracked, so EAS prebuilds from `app.json` and applies
   the plugin:

   ```bash
   eas build --profile preview --platform android     # and production for the AAB
   ```

6. **Verify**:
   - the build log shows `Sentry-CLI arguments:` and the map upload;
   - Sentry → *Releases* lists the release with `index.android.bundle` + `.map`;
   - a triggered JS error resolves to file/line instead of minified names.

To pause uploads *without* deleting the plugin entry (for example while a token is
being rotated), set `SENTRY_DISABLE_AUTO_UPLOAD=true` as an **EAS environment variable**
for that environment only — the switch then lives outside the repo instead of in
`eas.json`.

### Dependency install: no flags, no `.npmrc`

`package-lock.json` is kept **strict-resolution clean** (generated and verified with a
plain `npm install` / `npm ci`, no peer-dep flags), so the EAS *Install dependencies*
phase, CI, and local installs all work with plain npm. If you add dependencies, install
them the same way — do not commit an `.npmrc` with `legacy-peer-deps=true`, and do not
run `npm audit fix --force` (it rewrites major versions).

## 10. Troubleshooting

| Symptom | Cause / fix |
|---|---|
| App closes immediately after install, log says `Missing environment variables: ...` | The build did not receive the `EXPO_PUBLIC_*` values. `eas env:push <environment> --path .env --force`, then rebuild. |
| Map is blank in the APK | `EXPO_PUBLIC_GOOGLE_MAPS_ANDROID_API_KEY` missing from the EAS environment, or the key is restricted to a different package name/SHA-1. Restrict it to `com.househunter.app` + the EAS keystore SHA-1 (`eas credentials --platform android`). |
| Notification icon shows as a white blob / colored square | The small icon must be a white-on-transparent silhouette (`assets/notification-icon.png`, 96×96). |
| `eas env:push` fails with `Variable value can not be empty` | Your `.env` contains empty keys. Push a filtered file (see §3). |
| Build fails in **Install dependencies** | Lockfile out of sync with `package.json` — run a plain `npm install` and commit `package-lock.json` (no flags needed; see §8). |
| Gradle fails at `createBundleReleaseJsAndAssets_SentryUpload_...` / `Auth token is required` | The `@sentry/react-native` config plugin was re-added without a `SENTRY_AUTH_TOKEN`. Remove the plugin entry, or supply a token (§8). |
| `App not installed` when sideloading | An older build signed with another key is installed — uninstall it first. |
| Build fails in the **Fix gradlew** phase: `ENOENT .../android/gradlew` | A native `android/` folder was uploaded (committed, left on disk, or listed in `.gitignore` — see §1). Remove the folder from git and from disk, and keep `/android` out of `.gitignore`, then rebuild. |
| Build is unexpectedly using an old icon/permission | A committed `android/` directory overrides `app.json` (EAS then skips prebuild). Keep native folders untracked. |
| Pushes never arrive | FCM V1 service account key not registered — see §6. |
